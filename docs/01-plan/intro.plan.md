# 인트로 "바이브코딩이란?" — 계획서

> 대상 앱: 바이브코딩 스튜디오 (`vibe-coding-studio`)
> 상위 구상: 스튜디오를 초·중·고 전 학년이 쓰는 수업 툴로 확장 (인트로 → 0 → 1 → 2 선택지 → 3 → 4)
> 이 문서의 범위: **인트로 단계만.** 2단계 선택지(학년별), 노드 앱 연계는 후속 계획서에서 다룬다.

## 1. 목적

수업 맨 앞에서 학생이 **"바이브코딩이 뭐지?"**를 직접 체험하고, **"AI에게 한 줄 시키고 끝내지 말고 궁금해하자"**는 태도를 갖게 한다.
말하는 피아노 앱 블로그 초안(`docs/app-intro/talking-piano/blog-draft.md`)의 제작 이유를 수업 흐름으로 옮긴 것이다.

핵심 메시지 3가지
1. 바이브코딩 = 내 아이디어를 AI에게 **정확히 전달**해서 앱으로 만드는 것
2. 결과를 신기해하고 끝내지 않고 **"이건 어떻게 만들어졌지?"** 하고 묻는 것이 중요
3. 이런 것들을 만들 수 있다 (예: 목소리를 피아노로 바꾸는 앱)

## 2. 인트로 활동 흐름 (약 15~20분)

| 순서 | 활동 | 화면 | 소요 |
|---|---|---|---|
| ① | **분위기 잡기**: "뭐 만들어줘" 한 줄 → "오, 되네" 하고 끝나는 장면 보여주기. "여러분은 어때요?" 질문 | 인트로 페이지 | 2분 |
| ② | **체험**: 말하는 피아노를 새 탭으로 열어 **쉬움** 난이도로 듣고 퀴즈 맞혀보기 → 정답 확인 | 말하는 피아노 (새 탭) | 7분 |
| ③ | **"어떻게?" 질문하기**: 앱의 "앱 소개 · 원리 보기"를 읽고, 궁금한 점 1가지를 적기 | 말하는 피아노 → 인트로로 복귀 | 4분 |
| ④ | **설명**: 바이브코딩이란? 무엇을 만들 수 있나? (예시 카드 3~4개) | 인트로 페이지 | 3분 |
| ⑤ | **다리 놓기**: "이제 내 아이디어를 기획해 볼까?" → 0단계로 이동 | 인트로 페이지 | 1분 |

③에서 학생이 적은 "궁금한 점"은 `bridge.js` 데이터에 저장해 두고, 이후 3단계 결과나 제출 내용에 함께 담을 수 있게 한다(선택 사항, 6장 참고).

## 3. 화면 설계

### 3-1. 신규 파일: `intro.html` (스튜디오 안)
- 기존 페이지와 같은 디자인(색, 카드, 버튼)을 따른다. `shared/bridge.js` 사용.
- 구성: 헤더 → 활동 ①~⑤ 카드 순서대로 → 하단 "0단계로 이동" 버튼
- 각 활동 카드는 접힘/펼침이 아니라 **위에서 아래로 한 장씩** (수업에서 교사가 화면을 넘기며 진행하기 쉽게)
- 활동 ②는 "말하는 피아노 열기" 버튼 (새 탭)
- 활동 ③은 텍스트 입력칸 1개 ("궁금한 점을 적어보세요") + 저장 버튼
- 활동 ④는 "이런 것도 만들 수 있어요" 예시 카드 (스튜디오 앱들에서 3~4개 선정 — 7장에서 확정)

### 3-2. 수정 파일: `index.html`
- `stepDefs` 맨 앞에 인트로 단계 추가
  - `href: 'intro.html'`, 제목 "인트로: 바이브코딩이란?", **선택**, 완료 조건은 `data.introDone`
- 단계 번호 표시(`i + 1`)가 밀리지 않게 인트로는 번호 대신 아이콘(🎹) 사용 또는 "0단계"를 "1단계"로 재번호 중 택1 (7장 결정)
- 제목 "이렇게 4단계로 완성해요" 문구 정리 필요 (인트로 포함 시 숫자 표현 수정)

### 3-3. 수정 파일: `shared/bridge.js`
- 저장 항목 추가: `introDone`(완료 여부), `introQuestion`(③에서 적은 궁금한 점)
- 기존 `save()` 방식 그대로 사용 → 코드 변경 최소

### 3-4. 말하는 피아노 쪽 변경 — **없음**
- 허브 실행 주소를 그대로 새 탭으로 연다. 앱 코드는 수정하지 않는다. (돌아가기 배너는 후속 과제)

| 초등 저학년 | "원리 보기" 텍스트가 어려울 수 있음 | ③을 "궁금한 점 그림/말로 표현" 대안으로 교사가 구두 진행 가능하게 (코드 변경 없음, 안내문만) |

## 5. 제외 범위 (이번 인트로에서 하지 않는 것)
- 학년별 난이도 선택, 2단계 선택지, 노드 앱 연계 (후속 계획서)
- 인트로 결과의 클래스로그AI 제출 (스튜디오 최종 제출에 `introQuestion`을 포함할지는 6장에서 결정 후 진행)
- 말하는 피아노 기능 자체의 수정

## 6. 데이터와 제출
- `introQuestion`은 localStorage(`vcs_studio_data`)에만 저장한다. 서버로 보내지 않는다.
- 제출 포함 여부(선택): 3단계 제출 시 `textContent` 맨 앞에 "[인트로 질문] …"을 덧붙일지 결정이 필요하다. **기본값은 포함하지 않음.**

## 7. 결정이 필요한 사항 (추천 먼저)

1. **단계 번호**: 인트로를 번호 없는 🎹 카드로 두고 기존 0~4단계 번호는 유지 (추천) / 전체를 재번호
2. **활동 ④ 예시 카드**: 말하는 피아노 + 코드 스튜디오 계열 앱 중 3~4개 (목록은 확인 후 제안)
3. **`introQuestion` 제출 포함 여부**: 포함하지 않음 (추천)

## 10. 동작 확인 방법
- 스튜디오 `index.html` 첫 카드에 인트로가 보이고, 클릭하면 `intro.html`로 이동
- ② 버튼으로 말하는 피아노(허브 실행 주소)가 새 탭으로 열리고 바로 사용 가능 (로그인 없음)
- ③에서 궁금한 점을 저장 → 새로고침해도 유지, `index.html`에서 인트로가 완료(✓) 표시
- "진행 상황 초기화" 후 인트로 상태도 초기화됨
- 모바일/태블릿 폭에서 레이아웃 확인 (교실 태블릿 사용 가능성)
- 클래스로그AI 입장 링크(`?entryCode=...`)로 들어와도 기존 제출 흐름에 영향 없음
