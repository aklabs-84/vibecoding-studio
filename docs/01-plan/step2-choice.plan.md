# 2단계 "기획하기" 선택지 — 계획서

> 상위 구상: 인트로(완료) → 0 → 1 → **2 기획하기(선택지)** → 3 → 4
> 범위: 2단계를 **글 기획 / 노드 놀이터 / 노드 기획 PRO** 중 고르게 하고, 학년별 추천을 붙인다. 노드 앱의 결과를 스튜디오로 되돌려 받아 3단계(PRD 확인)와 4단계(CodeCanvas)가 그대로 동작하게 한다.
> 선행 문서: `intro.plan.md`

## 1. 현재 상태 (확인한 사실)

| 앱 | 2단계 역할 | 결과 형태 | 클래스로그AI 제출 |
|---|---|---|---|
| 스튜디오 `2-planner.html` | 5단계 질문 폼(문제정의→페르소나→기능→화면→앱정보) | `plannerText` + `plannerData` + `appName`을 `bridge.js`에 저장 | 3단계에서 제출 (구현됨) |
| 노드 놀이터 (`node-planner`) | 카드를 놓고 잇는 기획. 모드 3개: **앱 / 이미지 / 영상** | 기획서 글(`specApp`/`docImage`/`docVideo`) | 자체 `/api/submit` (구현됨) |
| 노드 기획 PRO | 노드 편집 → 점검 → AI 지시문 | 컴파일된 지시문 텍스트 | `CompilePanel.tsx`에서 `submitToClass` 호출 (구현됨) |

중요한 사실 두 가지
1. **세 앱은 서로 다른 주소(오리진)라 localStorage를 공유하지 못한다.** 결과를 넘기려면 주소(URL)나 메시지로 전달해야 한다.
2. 놀이터의 이미지·영상 모드는 "이미지/영상 만드는 AI용 프롬프트"를 만든다. 3단계·4단계는 **"실행 가능한 HTML 앱 코드"**를 만드는 흐름이라 맞지 않는다.

## 2. 학년별 구분 (제안)

| 수준 | 대상 | 추천 도구 | 이유 |
|---|---|---|---|
| 🌱 씨앗 | 초 저~중학년 | **노드 놀이터** (앱 모드) | 카드를 끌어다 놓는 방식이라 글쓰기 부담이 적음 |
| 🌿 새싹 | 초 고학년~중학교 | **글로 기획하기** (기존 2단계) 또는 놀이터 | 질문에 답하며 문장으로 정리하는 연습 |
| 🌳 나무 | 중 고학년~고등학교 | **노드 기획 PRO** | 화면 이동 흐름과 데이터를 점검(린트)하고 정확한 AI 지시문 생성 |

- 추천은 **"추천" 배지만 붙이고 막지 않는다.** 학생이 다른 도구를 골라도 된다.
- 수준 이름과 학년 경계는 교사가 바꿀 수 있게 상수 한 곳에 둔다.
- 교사가 입장 링크에 `?level=seed|sprout|tree`를 붙이면 수준 선택 단계를 건너뛴다(없으면 학생이 고름).

## 3. 화면 설계

### 3-1. 새 파일 `2-choose.html` (스튜디오)
- 위: 수준 선택(🌱 🌿 🌳 칩 3개). 선택하면 아래 카드의 "추천" 배지가 바뀐다.
- 아래: 도구 카드 3장
  - 📝 글로 기획하기 → `2-planner.html`
  - 🧩 노드 놀이터 → 놀이터로 이동 (앱 모드 고정)
  - 🕸 노드 기획 PRO → PRO로 이동
- 각 카드에 "이런 사람에게 맞아요" 한 줄 설명과 예상 시간.
- 돌아왔을 때 이미 결과가 있으면 "이미 기획서가 있어요. 다시 만들까요? / 3단계로 가기" 안내.

### 3-2. `index.html`
- 2단계 카드의 링크를 `2-planner.html` → `2-choose.html`로 변경 (완료 조건은 그대로 `plannerText`).

### 3-3. `shared/bridge.js` (추가 함수 2개)
- `buildNodeLaunchUrl(toolBaseUrl)`: 노드 앱으로 갈 주소를 만든다. 붙이는 값: `entryCode`, `studentName`, `studentId`(있을 때), `studio=1`, `returnUrl`(= `2-return` 처리 주소).
- `captureReturnFromHash()`: 돌아온 주소의 `#plan=…`을 읽어 `plannerText`, `appName`, `plannerSource`(`playground`|`pro`)를 저장하고 주소를 정리한다.

### 3-4. 노드 앱 쪽 (놀이터, PRO 각각)
- `?studio=1&returnUrl=…`이 있을 때만 **"스튜디오로 보내기"** 버튼을 보여준다. 없으면 지금과 똑같이 동작한다.
- 버튼을 누르면 기획서 글을 `#plan=`(base64url JSON)에 담아 `returnUrl`로 이동한다.
- 놀이터는 `studio=1`이면 **앱 모드로 고정**하고 이미지·영상 모드는 숨긴다(1장 2번 이유).
- 자체 제출 버튼(클래스로그AI)은 **그대로 유지**한다(결정 완료).

## 4. 결과 전달 방식 (결정: 같은 탭 이동 + 주소 해시)

```
스튜디오 2-choose ──(같은 탭 이동, entryCode 등을 쿼리로)──▶ 노드 앱
노드 앱 "스튜디오로 보내기" ──(같은 탭 이동, #plan=…)──▶ 스튜디오 3-result
```

| 방식 | 판단 |
|---|---|
| **해시(#)로 전달 (선택)** | 서버로 전송되지 않고, 팝업 차단·창 닫힘 문제가 없다. 노드 앱은 자기 작업을 자동 저장하므로 다시 돌아가 고칠 수 있다. |
| postMessage | 새 창이 열려 있어야 하고 학생이 창을 닫으면 끊긴다. |
| 복사·붙여넣기 | 항상 가능한 예비 수단. "스튜디오로 보내기"가 안 될 때 복사 버튼을 함께 둔다. |

해시 형식: `#plan=<base64url(JSON)>`, JSON = `{ v:1, source:'playground'|'pro', title, text }`. `text`는 18,000자로 자른다(기존 제출 한도와 동일).

## 5. 보안·개인정보 (필수)
- **`returnUrl` 허용 목록**: 노드 앱은 스튜디오의 실제 배포 주소(오리진)로만 돌려보낸다. 임의의 주소로는 보내지 않는다(결과를 엉뚱한 곳에 전달하거나 열린 리다이렉트로 악용되는 것 방지). `localhost`는 개발 중(호스트가 localhost일 때)에만 허용.
- 스튜디오는 받은 `plan`을 **글자로만** 다룬다(`textContent`, `innerHTML` 금지). `v`, 길이, `source` 값을 검증하고 틀리면 무시한다.
- `entryCode`와 학생 이름은 **해시가 아니라 쿼리로만** 보낸다. 되돌아올 때는 보내지 않는다(스튜디오가 이미 저장해 둠).
- 학생이 쓴 글을 AI 서버나 제3자 주소로 보내지 않는다. 전달 경로는 학생 브라우저 안(주소 이동)뿐이다.
- API 키는 건드리지 않는다. 각 앱의 기존 `/api/submit` 프록시를 그대로 쓴다.

## 6. 제외 범위
- 놀이터와 PRO의 노드 JSON 형식 통일, 놀이터에서 PRO로 이어서 편집
- 이미지·영상 기획을 코드 생성 흐름에 연결
- 노드 앱 기능 자체 개선, 학년별 맞춤 문구 전면 개편
- 스튜디오에서 노드 결과를 다시 불러와 편집하는 기능(되돌아가서 고치면 노드 앱이 자동 저장본을 보여 줌)

## 7. 구현 순서 (파일은 한 번에 하나씩, 각 단계 독립 확인)

| # | 파일 | 내용 | 확인 방법 |
|---|---|---|---|
| 1 | `vibe-coding-studio/shared/bridge.js` | `buildNodeLaunchUrl`, `captureReturnFromHash` 추가 | 콘솔에서 가짜 `#plan=`로 저장 확인 |
| 2 | `vibe-coding-studio/2-choose.html` | 수준 선택 + 도구 카드 | 수준 바꾸면 추천 배지 이동, 링크 주소 확인 |
| 3 | `vibe-coding-studio/index.html` | 2단계 링크 변경 | 클릭하면 2-choose로 이동 |
| 4 | `vibe-coding-studio/3-result.html` | `#plan` 수신 처리 연결(필요 시) | 가짜 `#plan`으로 열면 PRD·프롬프트에 반영 |
| 5 | `node-planner/index.html` | `studio=1` 처리(앱 모드 고정) + 보내기 버튼 + 허용 목록 | 쿼리 없이 열면 기존과 동일, 있으면 버튼 표시 |
| 6 | `node-planner-pro` (`lib/classlog.ts`, `CompilePanel.tsx`) | 같은 규칙 | 위와 동일, `npm test`·빌드 통과 |
| 7 | 전체 흐름 확인 | 스튜디오 → 노드 앱 → 스튜디오 → 3단계 → 제출 | 로컬 3개 서버로 한 번에 점검 |

- 1~4번은 노드 앱 없이도 가짜 해시로 먼저 검증할 수 있다.
- 5, 6번이 배포되기 전에 스튜디오만 먼저 배포되면 노드 카드가 "준비 중"으로 보이면 안 되므로, **스튜디오 푸시는 5, 6번 배포 후에** 한다(커밋·푸시는 사용자가 나중에 한 번에).

## 8. 동작 확인 체크리스트
- [ ] 수준 칩을 바꾸면 추천 배지가 이동하고, `?level=tree`로 열면 칩이 미리 선택됨
- [ ] 세 카드 모두 올바른 주소로 이동하고, 노드 앱에서 `entryCode`·`studentName`이 유지됨
- [ ] 노드 앱을 쿼리 없이 단독으로 열면 지금과 똑같이 동작(보내기 버튼 없음, 자체 제출 가능)
- [ ] 허용되지 않은 `returnUrl`로는 보내기 버튼이 나타나지 않음
- [ ] 3단계에 노드 결과가 `plannerText`로 들어가고 4단계 CodeCanvas 프롬프트에 포함됨
- [ ] 스튜디오 최종 제출 + 노드 앱 단독 제출이 둘 다 동작
- [ ] 잘못된 `#plan`(깨진 값, 너무 긴 값)을 넣어도 오류 없이 무시
- [ ] 모바일·태블릿 폭에서 카드 레이아웃 확인

## 9. 결정이 필요한 사항 (추천 먼저)

1. **스튜디오 실제 배포 주소**: 문서에 `vibecoding-akstudio.vercel.app`과 `vibe-coding-studio-orcin.vercel.app`이 둘 다 나온다. 수업에서 쓰는 주소 하나로 확정해야 허용 목록에 넣을 수 있다.
2. **학년 매핑**: 위 2장 표(씨앗·새싹·나무) 그대로 vs 수정
3. **놀이터 스튜디오 모드**: 앱 모드만 허용(추천) vs 이미지·영상도 허용(이 경우 코드 생성 단계는 건너뛰도록 별도 설계 필요)
